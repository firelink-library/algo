Kotlin é orientado a objetos — mas com uma abordagem bem mais concisa que o Java. Nesta seção vamos ver classes, herança, interfaces, data classes e sealed classes. Esses conceitos aparecem o tempo todo no desenvolvimento Android, especialmente quando você modela os dados do seu app.

## Classes

A declaração mínima de uma classe:

```kotlin
class Pessoa(val nome: String, var idade: Int)

val p = Pessoa("Ana", 25)
println(p.nome)   // Ana
println(p.idade)  // 25
p.idade = 26      // ok, var
```

Tudo que está no parêntese é o **construtor primário**. Com `val`/`var` ali, o Kotlin já cria as propriedades automaticamente — sem precisar de campos privados, getters e setters como no Java.

### Bloco init

Código que roda quando o objeto é criado:

```kotlin
class Conta(val titular: String, saldoInicial: Double) {

    var saldo = saldoInicial
        private set  // só pode ser alterado dentro da classe

    init {
        require(saldoInicial >= 0) { "Saldo inicial não pode ser negativo" }
    }

    fun depositar(valor: Double) {
        require(valor > 0) { "Valor deve ser positivo" }
        saldo += valor
    }
}
```

### Construtores secundários

```kotlin
class Produto(val nome: String, val preco: Double) {

    var descricao: String = ""

    // construtor secundário
    constructor(nome: String, preco: Double, descricao: String) : this(nome, preco) {
        this.descricao = descricao
    }
}
```

Na prática, construtores secundários raramente são necessários — parâmetros com valor padrão resolvem a maioria dos casos.

## Data Classes

São classes cuja função principal é guardar dados. O Kotlin gera automaticamente `equals`, `hashCode`, `toString` e `copy`:

```kotlin
data class Produto(
    val id: Int,
    val nome: String,
    val preco: Double,
    val disponivel: Boolean = true
)

val cafe = Produto(1, "Café", 12.90)
println(cafe)  // Produto(id=1, nome=Café, preco=12.9, disponivel=true)

// copy cria uma cópia alterando só o que você quer
val cafePromocional = cafe.copy(preco = 9.90)

// equals compara os valores, não a referência
val cafe2 = Produto(1, "Café", 12.90)
println(cafe == cafe2)  // true
```

:::tip[Data classes no Android]
Use data classes para modelar respostas de API, itens de lista e qualquer objeto que representa "um dado". No Android com MVVM/Clean Architecture, data classes são a base dos modelos de domínio e DTOs.
:::

## Herança

Por padrão, classes em Kotlin são **fechadas** (equivalente ao `final` do Java). Para permitir herança, você precisa marcar com `open`:

```kotlin
open class Animal(val nome: String) {
    open fun emitirSom() {
        println("...")
    }
}

class Cachorro(nome: String) : Animal(nome) {
    override fun emitirSom() {
        println("Au au!")
    }
}

class Gato(nome: String) : Animal(nome) {
    override fun emitirSom() {
        println("Miau!")
    }
}

val c = Cachorro("Rex")
c.emitirSom()  // Au au!
```

### Classes Abstratas

Quando a classe base não faz sentido ser instanciada diretamente:

```kotlin
abstract class Forma {
    abstract fun calcularArea(): Double
    abstract fun calcularPerimetro(): Double

    fun descricao(): String = "Área: ${calcularArea()}, Perímetro: ${calcularPerimetro()}"
}

class Retangulo(val largura: Double, val altura: Double) : Forma() {
    override fun calcularArea() = largura * altura
    override fun calcularPerimetro() = 2 * (largura + altura)
}
```

## Interfaces

Interfaces definem um contrato. Diferente de Java 7, interfaces Kotlin podem ter implementações padrão:

```kotlin
interface Clicavel {
    fun aoClicar()
    fun aoLongClicar() {
        println("Clique longo detectado")  // implementação padrão
    }
}

interface Arrastavel {
    fun aoArrastar(x: Float, y: Float)
}

// uma classe pode implementar múltiplas interfaces
class BotaoCustom : Clicavel, Arrastavel {
    override fun aoClicar() {
        println("Botão clicado!")
    }

    override fun aoArrastar(x: Float, y: Float) {
        println("Arrastando para $x, $y")
    }
}
```

## Sealed Classes

Sealed classes são fundamentais no Android moderno. Elas representam um conjunto **fechado** de subtipos — perfeitas para modelar estados de UI e resultados de operações:

```kotlin
sealed class ResultadoApi<out T> {
    data class Sucesso<T>(val dados: T) : ResultadoApi<T>()
    data class Erro(val mensagem: String) : ResultadoApi<Nothing>()
    object Carregando : ResultadoApi<Nothing>()
}
```

Com sealed classes, o `when` fica **exaustivo** — o compilador garante que você tratou todos os casos:

```kotlin
fun processarResultado(resultado: ResultadoApi<List<Produto>>) {
    when (resultado) {
        is ResultadoApi.Sucesso   -> exibirLista(resultado.dados)
        is ResultadoApi.Erro      -> exibirErro(resultado.mensagem)
        is ResultadoApi.Carregando -> exibirLoading()
        // sem 'else' necessário — o compilador sabe que cobrimos tudo
    }
}
```

## Companion Object

O equivalente a métodos e campos estáticos do Java:

```kotlin
class Usuario(val nome: String, val email: String) {

    companion object {
        const val ADMIN_EMAIL = "admin@app.com"

        fun criar(nome: String, email: String): Usuario {
            return Usuario(nome, email.lowercase())
        }
    }
}

// uso sem instanciar a classe
val admin = Usuario.criar("Admin", "ADMIN@APP.COM")
println(Usuario.ADMIN_EMAIL)  // admin@app.com
```

## Enum Classes

Para um conjunto fixo de constantes com comportamento:

```kotlin
enum class Status {
    ATIVO, INATIVO, PENDENTE
}

enum class Prioridade(val nivel: Int) {
    BAIXA(1), MEDIA(2), ALTA(3);

    fun ehCritica() = nivel >= 3
}

val p = Prioridade.ALTA
println(p.ehCritica())   // true
println(p.nivel)         // 3
```

## Object (Singleton)

Para criar um único objeto global sem precisar de classe:

```kotlin
object Configuracoes {
    const val BASE_URL = "https://api.meuapp.com"
    var timeout = 30

    fun resetar() {
        timeout = 30
    }
}

// acesso direto, sem instanciar
println(Configuracoes.BASE_URL)
Configuracoes.timeout = 60
```
