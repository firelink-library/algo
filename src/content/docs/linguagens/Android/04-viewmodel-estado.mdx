`ViewModel` é a camada responsável por manter e processar o estado da UI. Ele sobrevive a rotações de tela e separa a lógica de negócio da Activity ou Composable.

## 1. Por que usar ViewModel?

Quando o usuário gira o celular, a Activity é **destruída e recriada**. Se você guardar dados diretamente na Activity, perde tudo.

```
Usuário gira a tela
       ↓
Activity.onDestroy()   ← seus dados se perdem aqui
       ↓
Activity.onCreate()    ← começa do zero

Com ViewModel:
Activity.onDestroy()
       ↓                ← ViewModel continua vivo
Activity.onCreate()    ← ViewModel retorna o mesmo estado
```

Além disso, manter lógica na Activity/Fragment mistura responsabilidades — fica difícil de testar e manter.

## 2. Criando um ViewModel

Adicione a dependência no `build.gradle.kts`:

```kotlin
implementation("androidx.lifecycle:lifecycle-viewmodel-ktx:2.8.3")
implementation("androidx.lifecycle:lifecycle-runtime-ktx:2.8.3")
```

Crie o ViewModel:

```kotlin
class ContadorViewModel : ViewModel() {

    private val _contador = MutableStateFlow(0)
    val contador: StateFlow<Int> = _contador.asStateFlow()

    fun incrementar() {
        _contador.value++
    }

    fun decrementar() {
        if (_contador.value > 0) _contador.value--
    }
}
```

## 3. StateFlow

`StateFlow` é o contêiner de estado recomendado no Android moderno.

```
_contador (MutableStateFlow) ← ViewModel pode alterar
    ↓
 contador (StateFlow)        ← UI só pode ler
```

Esse padrão (privado mutável, público imutável) protege o estado de ser alterado de fora do ViewModel.

### Outras formas de expor estado

```kotlin
// LiveData (legado, ainda muito usado)
private val _nome = MutableLiveData<String>()
val nome: LiveData<String> = _nome

// StateFlow (moderno, prefira esse)
private val _nome = MutableStateFlow("")
val nome: StateFlow<String> = _nome.asStateFlow()

// State do Compose (para uso exclusivo com Compose)
var nome by mutableStateOf("")
    private set
```

## 4. Usando no Jetpack Compose

```kotlin
@Composable
fun TelaContador(viewModel: ContadorViewModel = viewModel()) {
    val contador by viewModel.contador.collectAsStateWithLifecycle()

    Column(
        horizontalAlignment = Alignment.CenterHorizontally,
        modifier = Modifier.fillMaxSize()
    ) {
        Text("$contador", style = MaterialTheme.typography.displayLarge)

        Row(horizontalArrangement = Arrangement.spacedBy(16.dp)) {
            Button(onClick = { viewModel.decrementar() }) { Text("-") }
            Button(onClick = { viewModel.incrementar() }) { Text("+") }
        }
    }
}
```

`collectAsStateWithLifecycle()` coleta o Flow respeitando o ciclo de vida — para a coleta quando a tela sai do foco.

## 5. Usando com XML (Activity/Fragment)

```kotlin
class ContadorActivity : AppCompatActivity() {

    private val viewModel: ContadorViewModel by viewModels()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        val binding = ActivityContadorBinding.inflate(layoutInflater)
        setContentView(binding.root)

        // observa o StateFlow
        lifecycleScope.launch {
            repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.contador.collect { valor ->
                    binding.tvContador.text = valor.toString()
                }
            }
        }

        binding.btnMais.setOnClickListener { viewModel.incrementar() }
        binding.btnMenos.setOnClickListener { viewModel.decrementar() }
    }
}
```

`repeatOnLifecycle(STARTED)` garante que a coleta para quando a Activity não está visível — economiza bateria e evita atualizações desnecessárias.

## 6. ViewModel com lógica real

```kotlin
data class Produto(val id: Int, val nome: String, val preco: Double)

sealed class UiState {
    object Loading : UiState()
    data class Success(val produtos: List<Produto>) : UiState()
    data class Error(val mensagem: String) : UiState()
}

class ProdutosViewModel(
    private val repositorio: ProdutoRepositorio
) : ViewModel() {

    private val _uiState = MutableStateFlow<UiState>(UiState.Loading)
    val uiState: StateFlow<UiState> = _uiState.asStateFlow()

    init {
        carregarProdutos()
    }

    fun carregarProdutos() {
        viewModelScope.launch {
            _uiState.value = UiState.Loading
            try {
                val produtos = repositorio.buscarTodos()
                _uiState.value = UiState.Success(produtos)
            } catch (e: Exception) {
                _uiState.value = UiState.Error(e.message ?: "Erro desconhecido")
            }
        }
    }
}
```

`viewModelScope` é um escopo de coroutine ligado ao ciclo de vida do ViewModel — quando o ViewModel é destruído, todas as coroutines são canceladas automaticamente.

## 7. Sealed class para estado de UI

O padrão `sealed class` para `UiState` é limpo e seguro:

```kotlin
@Composable
fun TelaProdutos(viewModel: ProdutosViewModel = viewModel()) {
    val estado by viewModel.uiState.collectAsStateWithLifecycle()

    when (val s = estado) {
        is UiState.Loading -> CircularProgressIndicator()
        is UiState.Error -> Text("Erro: ${s.mensagem}", color = MaterialTheme.colorScheme.error)
        is UiState.Success -> LazyColumn {
            items(s.produtos) { produto ->
                Text("${produto.nome} - R$ ${produto.preco}")
            }
        }
    }
}
```

O compilador exige que você trate todos os casos — sem risco de esquecer o estado de erro.

## 8. ViewModel Factory (injeção manual)

Quando o ViewModel precisa de dependências (como um repositório), use `ViewModelProvider.Factory`:

```kotlin
class ProdutosViewModelFactory(
    private val repositorio: ProdutoRepositorio
) : ViewModelProvider.Factory {
    override fun <T : ViewModel> create(modelClass: Class<T>): T {
        return ProdutosViewModel(repositorio) as T
    }
}

// na Activity ou Composable
val viewModel: ProdutosViewModel by viewModels {
    ProdutosViewModelFactory(ProdutoRepositorioImpl())
}
```

Em projetos maiores, use uma biblioteca de injeção de dependência como Hilt para fazer isso automaticamente.
